# Security Policy

The TarkovTracker-org team takes the security of our projects and our users' data seriously. This is the organization-wide default policy; individual repositories may define their own `SECURITY.md`, which takes precedence over this document.

## Supported Versions

Unless a repository states otherwise, only the **latest release** (and the default branch) of each project receives security fixes. We are a small volunteer team and cannot backport fixes to older versions.

## Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub issues, pull requests, or public Discord channels.**

Instead, use one of these private channels:

1. **GitHub private vulnerability reporting (preferred):** open the affected repository, go to the **Security** tab, and click **Report a vulnerability**.
2. **Discord:** send a direct message to an organization owner or maintainer on our [Discord server](https://discord.gg/PpdDwd2M6V).

### What to include

- A description of the vulnerability and its potential impact
- Steps to reproduce the issue, or a proof of concept
- The affected project, version, and environment
- Any suggested mitigation, if you have one

### What to expect

- We aim to acknowledge reports within **7 days**
- We will investigate, keep you informed of progress, and coordinate a fix and disclosure timeline with you
- Once a fix is released, we will credit you in the release notes (unless you prefer to remain anonymous)

We kindly ask that you give us a reasonable opportunity to address the issue before any public disclosure.

## Scope Notes

- Issues in **upstream dependencies** should also be reported to the relevant upstream project
- For **third-party services** we integrate with (e.g. Supabase, tarkov.dev), please report the issue to the service provider directly

Thank you for helping keep our community safe.
