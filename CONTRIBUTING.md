# Contributing to TarkovTracker-org

First off — thank you for considering a contribution! Our projects are community-driven, and contributions of every size and skill level are welcome.

> **Note:** This is the organization-wide default guide. Individual repositories may have their own `CONTRIBUTING.md` with project-specific setup instructions — if one exists, it takes precedence over this document.

## Code of Conduct

All participation is governed by our [Code of Conduct](CODE_OF_CONDUCT.md). By contributing, you agree to uphold it.

## Ways to Contribute

- **Report bugs** — open an issue using the *Bug report* template on the relevant repository
- **Suggest features** — open an issue using the *Feature request* template
- **Improve documentation** — typo fixes and clarifications are always appreciated
- **Submit code** — bug fixes, features, tests, and refactors via pull requests
- **Help others** — answer questions in issues, discussions, and [Discord](https://discord.gg/PpdDwd2M6V)

## Reporting Bugs

A good bug report includes:

- What you expected to happen vs. what actually happened
- Steps to reproduce the issue
- The project version (or app/commit) you're using
- Relevant logs, screenshots, or error messages

**Security issues:** please do **not** open public issues for security vulnerabilities. Follow our [security policy](SECURITY.md) instead.

## Pull Requests

1. **Fork** the repository and create a branch from the default branch
2. **Make your changes**, following the existing code style and conventions of the repository
3. **Test your changes** — run the project's tests, linters, and build locally when available
4. **Write clear commit messages** describing what changed and why
5. **Open a pull request** and fill out the template, linking any related issues (e.g. `Closes #123`)

A maintainer will review your PR as soon as possible. Reviews are collaborative — don't be discouraged by change requests; they're part of building something great together.

## Development Setup

Each repository has its own stack and setup instructions in its `README.md`. In general:

- Web projects use **Node.js** — install dependencies with the project's package manager, then use the documented `dev`, `build`, and `test` scripts
- Desktop and library projects document their toolchains individually
